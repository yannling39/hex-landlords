# 六手 Run 与个人海克斯规则规格

状态：本轮实现的规则基线。本文记录本轮讨论的决定，取代 GDD v1.2 中“三手 Run、仅保留海克斯占位接口”的相关安排；未列出的标准斗地主规则、叫分和计分公式沿用现有引擎。

## 1. 目标与节奏

- 一个 Run 固定六手斗地主，累计六手得分决定 Run 胜者。第六手结算后进入 `RUN_END`。
- 首叫玩家依次为 A、B、C、A、B、C，每人各首叫两次。地主仍由每手叫分决定，不保证各玩家成为地主的次数相同。
- 启用海克斯时，每名玩家在第 1 手开始前和第 3 手开始前各从三个候选中选一个。每人最多持有两个不同的海克斯；其他手不抽取、不替换。
- 持有的海克斯从选中起持续到本 Run 结束。限次资源在每手开始时恢复；绑定实体牌的状态在每手结束时失效。第 1、2 手各有一个海克斯，第 3 至第 6 手各有两个。
- 关闭海克斯时仍进行完整六手 Run，跳过全部抽取和能力准备阶段。

这个安排让玩家有两手熟悉第一项能力，再用四手探索两项能力的组合。六手会增加单次 Run 的时长；先保持标准斗地主的胜负和计分，不添加强行结束单手的轮数上限。需要用实测的单手耗时、Run 完成率和重复操作耗时决定是否缩短 AI 展示延迟。

## 2. 抽取与持有

- 两次抽取都发生在本手的发牌数据已由权威状态准备好、但叫地主尚未开始时。抽取期间不向玩家展示本手手牌和底牌，确保第 1、3 手的选牌信息条件一致。预生成的发牌数据始终只留在权威状态中。
- A、B、C 各自按顺序选择。每位玩家看到自己的三个候选；已拥有的海克斯不再进入自己的候选池。不同玩家可以拥有同名海克斯。
- 候选生成必须由 Run 种子确定，不能在 reducer 中调用非确定性的随机数。相同种子和相同命令序列得到相同候选与牌局。
- 已选海克斯及持有者为公开信息；未轮到该玩家选择前，其候选只对本人可见。第二次选择完成后不再生成候选。
- 六条海克斯构成首版完整候选池。每名玩家在每次抽取中看到其中三个互异候选；候选权重、保底和刷新暂不加入首版。

## 3. 通用裁定

- 海克斯是个人能力。没有持有相应海克斯的玩家不能主动声明该特殊出法，但仍可按桌面最终牌型使用普通规则跟牌。
- 每次 `PLAY` 最多声明一种改变牌型构成的海克斯：共鸣、断章、同色协定互斥。没有声明时仅按实体牌的普通牌型解析。逆流是领出时设定的整墩比较模式；尊我为王是指定实体牌的单张属性，不占上述声明位置。
- 同一组实体牌可能存在多种合法解释。玩家提交明确声明，权威规则层据此解析，并把解析后的牌型、比较值和声明写入公开出牌事件及 `lastPlay`。UI 或 AI 不能自行决定服务器采用哪种解释。
- 炸弹和王炸仍可压制全部普通牌型；王炸仍高于炸弹。尊我为王的“大于大王”只指单张牌力，不改变炸弹/王炸的跨牌型优先级。所有现有炸弹倍数规则不变。
- 非法命令不扣次数、不改变手牌和墩状态，也不产生事件。成功出牌后若手牌为空，仍立即结束该手。
- 若多名玩家各有一张尊王单张，两张牌牌力同级；同级不能互相压制。不同玩家的其他同名海克斯照常分别生效。

## 4. 海克斯信息表

| ID / 名称 | 持有者的精确效果 | 对手的合法应对 | 每手状态与节奏边界 |
| --- | --- | --- | --- |
| `resonance` 共鸣 | 一次普通出牌中，最多选一张实体点数为 3、6、9、Q 的牌，声明其在本次出牌中的有效点数为这四者之一。仅在换成另一点数时视为发动；不能用于单张、炸弹、王炸，也不能借此组成四张同点数的主体。可用于对子、三张、顺子、连对、飞机及其附带牌等其余现有普通牌型。 | 按已解析的最终牌型、长度和主牌值跟牌。 | 无发动次数限制；每次最多一张牌替换，并要求明确声明实体牌 ID 和目标点数，以限制搜索和歧义。 |
| `broken_straight` 断章 | 可将 5 至 11 张点数互异、处于 3 至 A 范围的牌声明为顺子；其最小与最大点数之间恰好缺一个内部点数，例如 3、4、5、7、8。按实际最大点数和实际出牌张数比较。 | 用同张数、主牌值更高的普通顺子或本人特殊顺子跟牌；炸弹和王炸照常可压。 | 无次数限制。只影响单张顺子，不扩展到连对、飞机；不允许首尾“缺口”或 2、王。 |
| `abandon` 弃守 | 每手一次，在合法跟牌回合提交 `PASS` 时，同时公开弃掉自己手中一张指定实体牌。不能弃掉最后一张牌；不能在领出时使用。 | 视为一次普通 Pass，按原顺序继续行动。弃掉的牌不进入桌面牌型，不可被跟牌。 | 记录本手已用标记及公开弃牌。弃牌不算 `PLAY`、不改变炸弹倍数、不触发手牌清空胜利。若弃掉尊王指定牌，其单张效果同时结束。 |
| `reverse_flow` 逆流 | 持有者领出单张或对子时，可声明本墩倒序比较。3 至 A 的点数顺序反转；2、小王、大王仍依次高于这一组。只对本墩的单张或对子比较生效。 | 所有人按同一倒序规则跟牌；炸弹、王炸照常可压。 | 本墩记录 `normal/reverse`；连续两人 Pass 收墩后清空。持有者独占发动时机，但倒序也可能让对手受益，是重点平衡项。 |
| `same_color` 同色协定 | 每手最多一次，可声明恰好五张均为红色（红桃/方块）或均为黑色（黑桃/梅花）的实体牌为五张顺子。牌中不得有 2 或王；有效主牌值是五张牌的实际最高点数。 | 可用主牌值更高的普通五张顺子跟牌；持有同海克斯者也可用其特殊顺子跟牌；炸弹、王炸照常可压。 | 每手初始 1 次，成功出牌才扣减。允许重复点数，但必须是五张不同实体牌；不与共鸣或断章在同次出牌叠加。最高点数低于普通五张顺子的最低主牌值 7 时仍可领出，只是容易被压。 |
| `crown_me` 尊我为王 | 地主确定并取得底牌后、第一张牌打出前，持有者从当手手牌中公开指定一张实体牌。该牌作为单张打出时，单张牌力大于大王；用于任何其他牌型时按原点数结算。 | 可用炸弹或王炸压制该单张；也可以争夺多张牌型的牌权。 | 每手重新指定。公开该牌的 ID/点数/花色及持有者；一旦它被打出或弃掉，能力即消耗。不能将同点数其他牌一并视为最大单张。 |

“每手最多一次”的同色协定，以及共鸣不能形成四张主体，属于首版保守数值。同色五张在 17 至 20 张手牌中通常容易凑齐；每手两次可能让持有者反复把十张散牌直接变为顺子，过度压缩回合。上线测试时优先观察这两项的使用率和胜率，再调整数值，不在实现中散布隐式例外。

## 5. 状态机与数据边界

启用海克斯时，阶段顺序为：

```text
RUN_START -> HEX_DRAFT(hand 1) -> BID -> [KING_DESIGNATE] -> PLAY
  -> HAND_END -> NEXT_HAND(hand 2) -> BID -> [KING_DESIGNATE] -> PLAY
  -> HAND_END -> NEXT_HAND(hand 3) -> HEX_DRAFT -> BID -> [KING_DESIGNATE] -> PLAY
  -> HAND_END -> NEXT_HAND(hand 4/5/6) -> BID -> [KING_DESIGNATE] -> PLAY
  -> HAND_END(hand 6) -> RUN_END
```

方括号阶段仅在本手有尊我为王持有者时出现。`KING_DESIGNATE` 应由 A、B、C 中的持有者依次提交指定，全部完成后由地主领出。若该手叫地主阶段全员不叫而重发，尚未进入指定阶段，已选海克斯不变。关闭海克斯时不进入 `HEX_DRAFT` 或 `KING_DESIGNATE`。

### 权威状态

- `handNumber` 扩展为 1 至 6；`preparedDeals` 为六手各准备最多三次发牌。第 6 手才结算 Run，首叫位按现有环形逻辑轮转。
- `hexPicks` 保存稳定海克斯 ID，不把运行次数塞进候选展示文案。新增每手运行状态：弃守是否已用、同色剩余次数、各玩家尊王指定 `cardId`、当前墩的比较模式、公开弃牌区。
- `lastPlay` 保存经声明解析的最终牌型及必要的海克斯来源，以保证后续跟牌和回放使用相同裁定；手牌中的实体牌点数本身不变。
- 开始下一手时清空上手的指定牌、弃牌区、次数与墩模式；保留持有的海克斯和 Run 总分。Run 重开则全部重置。
- 当前 `GameState.version` 为 1。若将来接入存档或网络状态持久化，新增字段时应提升版本并定义迁移；本地 MVP 目前不读旧存档。

### 命令与事件

- `SELECT_HEX` 仍用于抽取，但仅允许第 1、3 手的指定窗口使用；候选资格由权威状态校验。
- 新增 `DESIGNATE_KING`，传入本人手中的一个 `cardId`。公开事件记录玩家和指定实体牌。
- `PLAY` 增加可选、带标签的出法声明：共鸣的 `cardId + 目标点数`、断章、同色协定，以及领出时的逆流标志。错误声明不得悄悄回退为普通牌型。
- `PASS` 可携带可选弃牌 `cardId`；没有指定牌时保持现有普通 Pass 行为。公开事件区分普通 Pass 与弃守，并记录弃牌。
- 事件应能让牌桌、日志和回放展示“实体牌是什么、被当成什么牌型、哪条海克斯生效、次数如何变化”。

### 解析、比较和 AI

- 统一的规则解析入口接收实体牌、玩家持有的海克斯、出法声明与本墩上下文，输出规范化出牌结果。`pattern.ts` 保留普通牌型识别，海克斯解析作为领域层适配；`compare.ts` 在普通炸弹优先级之外读取墩模式和尊王单张属性。
- `legal-plays.ts` 返回带声明的合法行动候选，而不只返回 `CardId[][]`。同一组牌有普通和特殊两种合法解释时返回可区分的候选；使用按点数分组的候选生成，避免在 20 张地主手牌上为多个海克斯盲目枚举所有组合。
- 人类和 AI 均提交相同命令并经同一 `dispatch` 校验。AI 需要决定何时保留指定王牌、是否发动逆流、何时使用弃守/同色；农民 AI 还应避免无故压过队友。首版可以用简单启发式，但不能完全不使用能力。
- 玩家视图只暴露自己的手牌、公开的已选海克斯、公开的尊王实体牌、已使用次数和公开弃牌；不得因候选生成或第 1/3 手抽取泄漏别人的手牌、底牌或未来发牌。

## 7. 验收与平衡观察

- 关闭海克斯时，固定种子能完整跑完六手；首叫位为 A/B/C/A/B/C，最终仅产生一次 `RUN_FINISHED`。
- 开启海克斯时，每位玩家只在第 1、3 手各选一个，总计两个互异持有项；第 1/2 手一个、第 3 至 6 手两个；同种子同命令回放一致。
- 每条海克斯均覆盖合法使用、非法资格或时机、标准反制、次数或实体牌消耗、跨手重置；错误动作状态完全不变。
- 共鸣、断章、同色的声明与普通解释可区分；逆流收墩即清除；尊王单张高于大王但输给炸弹/王炸；弃守不可能直接出完手牌。
- 每个 AI 候选都能被 `dispatch` 接受。持续六手时不卡在抽取/指定阶段，牌数守恒，隐藏信息不泄漏，浏览器 UI 能完成整段 Run。
- 记录每手耗时、每手出牌/Pass 次数、各海克斯发动次数、按持有海克斯与地主/农民身份分组的胜率。重点观察共鸣+断章的清牌速度、同色协定的五张出牌频率、逆流的实际收益，以及尊王留到两张手牌时的收尾胜率。数据不足前不改变标准结算公式。

## 8. 实施顺序

1. 先扩展六手 Run 与第 1/3 手抽取阶段，保持海克斯效果关闭；验证状态转移和前端完整流程。
2. 接入稳定海克斯 ID、每手运行状态及带声明的出牌结果，再逐条实现共鸣、断章、同色协定、逆流、弃守、尊我为王。
3. 接通合法行动枚举、AI、玩家视图和 UI 控件，完成固定种子全程回归及平衡数据采集。
