# 斗地主前端设计规格

## 目标

在现有 TypeScript 斗地主规则引擎之上增加可交互的浏览器牌桌。玩家固定使用 A，与 B、C 两个本地 AI 完成叫地主、出牌和三手 Run。前端以真实规则引擎为唯一规则来源，支持直接验收当前单机 MVP。

本规格承接已确认的方向：Vite + React + TypeScript；界面只读 `PlayerView` 并提交 `Command`；本地对局适配层持有完整状态并调用规则引擎；未来可替换为房主服务器适配层。

## 用户流程

1. 打开页面即进入牌桌，使用固定人类玩家 A 和 AI 玩家 B、C。
2. 按当前回合进行叫分。人类可选择不叫或当前合法的叫分；AI 只在各自回合行动。叫到 3 分时立即确定地主；连续全员不叫按规则重发，第三轮仍不叫则由首叫玩家自动成为地主。
3. 地主确定后公开三张底牌，并将其加入地主手牌。人类回合可选择手牌并出牌；跟牌时可 Pass。非人类回合由 AI 自动处理。
4. 一方出完牌后显示本手胜负、倍数和分数变化，并允许继续下一手，直至三手 Run 结束。
5. 页面提供重新开始操作，重新开始使用确定的默认种子，方便复现验收过程。

## 技术架构

### 前端与领域层

- Vite 提供本地开发服务器和浏览器构建。
- React + TypeScript 实现牌桌交互；React 只依赖领域模块公开的数据类型和函数，不进入领域层。
- 规则模块保持无 DOM、React、网络和浏览器存储依赖。
- 使用现有 Node 测试保持领域层回归；前端交互通过独立组件/控制器测试，以及真实浏览器验收覆盖。

### 本地对局适配层

新增本地对局适配层作为 UI 与引擎之间的边界。适配层负责：

- 创建和持有完整 `GameState`。
- 接收人类 `Command`，通过 `dispatch` 运行规则。
- 每次人类动作后依次驱动 AI，直至轮到 A 或牌局进入结算状态。
- 在手牌结束时调用 `settleHand`；进入 `NEXT_HAND` 时调用 `startNextHand`。
- 对 UI 只返回 `viewForPlayer(state, 'A')` 的投影和本次公开事件。
- 将规则错误转为可展示的用户提示，失败命令不推进状态。

适配层定义异步小型 `GameClient` 接口，以玩家视图读取和命令提交为中心；本地实现也返回 Promise，以保持两种传输边界一致。第一版只实现本地客户端。未来网络客户端可实现同一接口并调用服务端，UI 不保存或接收完整权威状态。

### 界面组件边界

- `App` 管理屏幕级视图、忙碌状态和提示。
- `GameTable` 展示牌桌、玩家位置、手牌数量、当前墩、倍数、分数及事件记录。
- `PlayerHand` 展示 A 的手牌和选中状态。
- `BidControls` 展示当前合法叫分选项。
- `PlayControls` 提供出牌和 Pass；领出时隐藏/禁用 Pass。
- `HandResult` 和 `RunResult` 展示结算及继续/重开操作。
- 组件通过回调提交用户意图，不自行判断牌型或修改规则状态。

## 视觉与交互

- 首页直接显示牌桌，不增加营销页或功能说明页。
- 桌面布局：对手信息在桌面上方，牌桌中央展示当前墩和行动提示，底部放玩家手牌与操作区。
- 窄屏布局：玩家手牌固定在底部操作区域附近；桌面信息按纵向顺序折叠，手牌始终可见且可操作。
- 颜色令牌：牌桌深绿 `#12372E`，桌面绿 `#22694F`，牌面 `#F5F2E9`，红花色 `#C6433F`，地主/倍数强调 `#D3AE61`。文本和交互状态须满足可读性对比。
- 中文正文使用系统无衬线字体栈，以免依赖运行时网络字体；点数和花色在牌面上清晰呈现。
- 手牌具有稳定尺寸；选择后通过明确的位移/描边表示，不导致周边牌面或布局抖动。动画只用于选牌、出牌和结果揭示，并尊重减少动态效果设置。
- 所有按钮可键盘聚焦；键盘 Enter/Space 可触发，焦点样式清晰。按钮文字直接描述动作。
- 用清晰状态文字说明轮到谁行动、能否叫分/出牌和拒绝原因；不展示技术错误码。

## 状态与安全边界

- React 视图状态只包含 `PlayerView`、选中的 `CardId[]`、本地提示及公开事件记录。
- 不允许 UI 从完整 `GameState` 读取对手手牌、未公开底牌、重发牌或未来牌局。
- AI 只能收到各自的 `viewForPlayer` 结果。
- 人类出牌必须提交确切的选中 `CardId[]`；领域引擎负责最终校验，UI 可展示预校验反馈但不能替代 reducer。
- `GameClient` 的本地实现和后续远程实现都返回玩家视图与公开事件；远程传输不属于本规格。
- 刷新页面后是否恢复牌局不作保证；第一版不增加存储。

## 错误处理

- 对非法叫分、不能压过当前牌、手牌归属无效等领域错误，保留当前视图和选牌，显示可理解的短提示。
- 输入提交期间暂时禁用重复动作，命令完成后恢复交互。
- 任一非预期异常以不泄露隐藏状态为原则显示通用错误和重新开始入口；开发模式保留控制台诊断。
- AI 仅在轮到对应玩家时被驱动；AI 命令被规则拒绝视为实现错误，不静默跳过或伪造状态。

## 验收标准

- `npm run dev` 可启动本地页面；页面适配桌面和窄屏视口。
- 新游戏显示 A 的 17 张手牌，B/C 各 17 张；未叫地主时底牌不公开。
- 人类可完整执行不叫/叫分、选择牌、出牌和 Pass；非法提交会显示提示且牌局状态不变。
- 两个 AI 会在各自回合自动行动，且无法从 A 的界面读取对方牌值。
- 地主底牌公开并加入地主手牌；炸弹/王炸倍数变化、手牌胜负、分数变化和首叫轮换可见。
- 可完成三手 Run 并重开一局；同一默认种子会得到相同的发牌及 AI 行动结果。
- 领域 `npm test` 与 `npm run build` 继续通过；浏览器交互覆盖开始、叫分、出牌、Pass、手牌结束、三手结算和重开。
- UI 仅依赖 `GameClient`、`PlayerView` 和 `Command`，不直接消费内部 `GameState`。

## 不在范围

WebSocket 或其他联机传输、房间管理、账号/匹配、持久化、玩家座位选择、真人联机、海克斯强化、复杂 AI、拖放牌型建议、牌桌音效和完整动画演出。

## 关键设计决定

- 第一版采用浏览器页面而非桌面壳：Vite 可直接运行现有 TypeScript 领域层，也能复用未来房主服务器的数据边界。
- 第一版固定用户为 A，不增加座位选择；这样可把实现重点放在完整对局交互，并验证 A/B/C 轮换。
- 规则裁定留在 reducer；UI 仅负责输入、展示和易读反馈，避免出现第二套牌型逻辑。
- 本地与未来远程对局通过客户端适配接口隔离，当前不实现网络层。
